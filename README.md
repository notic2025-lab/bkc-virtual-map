# 立命館大学BKC バーチャルキャンパスマップ 🏫

立命館大学 びわこ・くさつキャンパス（BKC）の公式キャンパスマップを元に、
探索して楽しい **3Dバーチャルキャンパス** として再構築したWebアプリ。
学生・教職員・来訪者が「いま居る場所から目的の建物まで」最短で辿り着けることを目的にしています。

## 起動方法

```bash
cd BKC_map
python3 -m http.server 8931
# → http://localhost:8931 をブラウザで開く
```

ビルド不要・依存ゼロ（Three.js は `vendor/` に同梱、CDN不要）。

## 機能

- **3Dバーチャルキャンパス** — 公式マップの全44棟＋スタジアム・グラウンド・池・並木を立体表現。地面（芝生・通路・トラック・池）は画像アセットに依存せず Canvas で手続き生成
- **大学生活目線のカテゴリ** — 「授業・自習 / 食堂・カフェ / 履修・相談 / 研究・実験棟 / スポーツ / 課外・サークル / 生活・設備」で色分け・フィルタ
- **学生語彙での検索** — 「食堂」「図書館」「学びステーション」「保健センター」「部室」などの言い回しでヒット（あいまい検索つき）
- **経路案内 (A→B)** — キャンパス内の通路ネットワーク上を A* 探索して光るルート＋動く矢印で表示。距離・徒歩時間の目安つき
- **GPSナビ** — 許可済みの場合は起動時から現在地へ追従。未許可の場合は「現在地」「ナビ」「共有」を選んだ時点で許可を確認し、逸脱時は自動リルート
- **🚶 クラウド歩行学習** — ユーザーが歩くほど地図が賢くなる。キャンパス内の移動を「約6mグリッドのセル間通行量」として匿名集計（Firebase RTDB）し、①よく歩かれる通路を経路探索で優先、②どの通路にも無いのに多く歩かれる区間を「みんなの道（ショートカット）」として自動でグラフに追加（建物内を通る誤学習はフットプリント判定で除外）、③学習した道は金色ラインで地図に表示。個人ID・タイムスタンプ・生の軌跡は一切送信しない
- **📱 ARナビ** — カメラ映像の上に進行方向のシェブロン矢印をオーバーレイ（コンパス追従、非対応環境はシミュレーション表示）
- **📱 PWA** — Service Worker によるオフラインキャッシュ。ホーム画面に追加してアプリのように使える

## 堅牢性・スケーラビリティ（同時3000人対応の考え方）

- **完全静的サイト** — サーバーサイド処理ゼロ。GitHub Pages / Cloudflare Pages などのCDNから配信すれば、同時アクセス数はCDNの限界（実質無制限）までスケールする
- **通常利用時の外部リクエストゼロ** — ロゴ・アイコンはSVGを自前生成、フォントもシステムフォント。ライブ共有を選んだ場合のみFirebaseへ接続
- **Service Worker キャッシュ** — 再訪時はネットワーク不要。イベント等で一斉アクセスが起きても、オリジンへの負荷は初回取得分のみ
- **フェイルソフト設計** — GPS拒否・カメラ非対応・WebGLコンテキストロスト・SW登録失敗のいずれでも、機能を落として動作継続

## 📐 現地測量モード — 通路・入口・建物名を現地確認する

マップの精度は略図ベースの推定から始まります。現地測量モードでは、通路の生GPS、
建物入口、建物名称の確認結果を端末に保存し、実測データとして書き出せます。
スマホGPSには数m以上の誤差があり得るため、生の1軌跡を完成地図とは扱わず、往復測定・
外れ値除去・複数軌跡の平均化・検証点での照合をしてから採用してください。

### 手順

1. PCで次を実行する（初回だけ `ngrok config add-authtoken ...` が必要）

   ```bash
   node tools/survey-server.mjs
   ```

   表示された専用HTTPS URLをスマホで開き、位置情報を許可する。URLには起動ごとのランダム同期鍵が入り、
   スマホの作業状態はPCの `survey-backups/latest-state.json` に自動バックアップされる。
   端末側のデータを失った場合は、同じ専用URLで開いて **「PCから復元」** を押せば再開できる。
   調査中はPCとこのコマンドを起動したままにする。公開済みサイトを使う場合は従来どおり
   **`https://<公開URL>/?survey`** でもよい（この場合はスマホ内保存のみ）。
   - 画面上部の調査ガイドが、現在地と進捗から次に行う調査を自動提示する
   - 15分・30分・60分から残り時間を選ぶと、情報価値と移動時間から再計画する
2. **「記録を開始」** を押し、通路の中央を往路・復路の両方で歩く
   - 約6mごとに通路ノードが自動記録され、水色の線でつながっていく
   - 完成地図用ノードはGPS精度±5m以内だけ採用（±30mまでは品質分析用の生ログだけ保存）
   - 精度・時刻を含む生GPSは±30m以内を `tracks` に保存し、後処理に利用できる
   - 交差点で別の道に入るときはそのまま歩けばOK。一度停止→再開すると新しい道として記録され、近くの既存ノードに自動接続される
3. 建物前では **「建物名をチェック」** を開く
   - 現地表示と一致する場合は「名称OK」
   - 違う場合は「名称を修正」を選び、現地の名称とメモを入力
   - 「保存＋入口測定」を押すと、15秒間の複数GPS測位の中央値で入口を記録
   - 入口座標と建物本体の中心座標は別データとして保持される
   - 同じ建物で繰り返すと複数入口を保存でき、ナビ時は現在地から最適な入口を選ぶ
4. 記録は端末に自動保存（アプリを閉じても消えない）。間違えたら **戻す** で取り消し
5. 歩き終えたら **「書き出し」** → `survey-data.js` がダウンロード＆クリップボードにコピーされる
   - 同時に `bkc-survey.geojson` も生成され、GISで生の実測形状を確認できる
6. 往復軌跡を後処理・確認後、リポジトリの `js/survey-data.js` をその内容で置き換えて push
   （`sw.js` の `CACHE_VERSION` も変えるとキャッシュ済み端末にも確実に配信される）
7. キャンパス全域を歩き終えたら **「略図の通路を置き換える」** をONにしてエクスポート → 推定の通路が消え、実測グラフのみでナビするようになる
   - 下記の全完成基準を満たして進捗100%になるまではONにできない
   - 公開用グラフは往路・復路を平均化し、交差点端点と建物入口を自動接続して生成される

### 自動調査ガイドの完成基準

- 正門・東門・バスターミナル・セントラルサーカスの基準点が有効精度で測定済み
- 全通路が両方向から測定済み
- 全建物の名称が「名称OK」または修正名称で確認済み
- 全建物入口が複数GPS測位の中央値で測定済み
- 全建物外周が閉合条件・面積条件・GPS品質を満たす
- 全GPSログのうち精度±5m以内が70%以上

1項目でも不足していれば100%表示にならず、調査ガイドが再測定箇所を提示し続けます。

測量は一度に終える必要はありません。何回かに分けて歩いてもデータは端末に蓄積され、
エクスポートのたびに全データが出力されます。

## 🔒 セキュリティと運用

- **Firebase Realtime Database のルール**は必ず [firebase.rules.json](firebase.rules.json) の内容を
  コンソールの「ルール」タブに貼り付けて公開すること。書き込みをメンバー単位に限定し、
  データの型・文字数・座標範囲・不明キーの拒否までサーバー側で検証する
  （部屋ごと消す攻撃・巨大データ注入・不正な形のデータをDB側で遮断する）
- `js/firebase-config.js` の apiKey はFirebase Webアプリの仕様上「公開情報」。
  秘密はルール側で守る設計であり、キー削除やコード秘匿は不要
- ページには **CSP**（Content-Security-Policy）を設定済み。実行できるスクリプトは
  自ホストと gstatic（Firebase SDK）のみ。`index.html` の importmap を書き換えた場合は
  CSPコメントの手順どおり sha256 ハッシュを再計算すること
- ライブ共有で受信するデータは**すべて信頼できない入力として検証**してから描画する
  （キー形式・型・鮮度・座標範囲・件数上限・HTMLエスケープ）
- **デプロイ前チェック**: `node tools/validate-data.mjs` で通路グラフの連結性と
  データ整合性を検証する（survey-data.js 更新時は必須）

## スマホで使う場合（GPS・AR含む）

カメラ・GPS・コンパスは HTTPS または localhost が必要です。現地調査では次のコマンドを使うと、
ngrokのHTTPS化とPCへの自動バックアップが同時に起動します。

```bash
node tools/survey-server.mjs
```

iPhone は初回にコンパス利用の許可ダイアログが出ます。

## データについて

建物名・施設内容は公式キャンパスマップ（2026-07時点）から取得。
配置は公式イラストマップを元にした **デフォルメ略図** です（位置関係は概略）。
`js/data.js` に集約してあるので、建物の追加・移設はこのファイルだけ更新すれば反映されます。

略図の間は `js/data.js` の推定 `GEO` を使用します。全域調査後の書き出しでは、
実測グラフからキャンパスの主軸・中心緯度経度・表示縮尺を算出して `survey-data.js` へ自動保存するため、
公開版で `rotationDeg` や `lat0/lng0` を手作業調整する必要はありません。

## 構成

```
index.html            … UIレイアウト・PWA登録
css/style.css         … デザイン（立命館クリムゾン＋昼光ベースの案内地図UI）
js/data.js            … 建物 / 施設 / 通路グラフ / GPSジオリファレンス
js/app.js             … 3Dシーン・地面生成・経路探索・GPSナビ・UI
js/survey.js          … スマホ現地測定UI・品質判定・PC同期・書き出し
js/survey-planner.js  … 情報利得ベースの調査指示・ロバスト後処理・完成判定
js/survey-data.js     … 公開版へ反映する実測データ
js/ar.js              … ARナビ（カメラ + コンパス + Three.jsオーバーレイ）
tools/survey-server.mjs … 調査用HTTPS起動・鍵付きPCバックアップ
sw.js                 … Service Worker（オフラインキャッシュ）
manifest.webmanifest  … PWAマニフェスト
vendor/               … Three.js 同梱
assets/               … アイコン（旧GFO版のフロア画像は未使用）
```
